# 日报生成 Skill

## 职责

把 `dingtalk-collector` 提取的消息（证据）蒸馏成上级愿意看的日报。
**单次调用型 skill**：无工具调用、无分支，代码组装提示词 → AI 一次产出。

## 输入（stdin JSON 或 config.yaml 的 report 段）

| 字段 | 必填 | 说明 |
|------|------|------|
| messages | 是 | collector 输出的消息列表 |
| corrections | 否 | 历史修正记录（修正层），有则必读 |

## 蒸馏纪律（对 AI 的铁律）

1. **只写有证据的内容**——每条总结都要能指回某条消息，不许编造
2. 没有产出就写"今日无产出"，不许灌水
3. 同类消息合并成一条（发 5 次进度 ≠ 5 项工作）
4. 保留具体信息：接口名、版本号、数字——"修复了登录 bug" ❌ "修复 1.4.9 版本登录超时（>3s 降为 0.8s）" ✅
5. **修正层最高优先**：corrections 里记过的错误，本次绝不再犯

## 输出格式（Markdown，固定模板）

```markdown
# 工作日报 (YYYY-MM-DD)
## 今日完成
1. 【主题】具体描述
## 进行中
1. 【主题】具体描述
## 风险与阻塞
1. 【主题】具体描述（没有就写"无"）
```

- 编号用 `1. 2. 3.`，每条 = `【≤8字主题】一句话描述（带硬信息、无铺垫）`
- 完整格式规范见 `prompts/summarize.md`——SKILL.md 只说形状，细节在提示词里
